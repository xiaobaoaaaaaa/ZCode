# Personal profile import

Two methods: preview an explicitly selected official profile; confirm that exact expiring preview. This memory category supports project Markdown layout verified against upstream 3.16.2; it opens no SQLite or credential files. One adapter owns the in-memory lease and serial admission; no background work. Destination root is injected by MemoryService, never supplied by RPC/UI. All existing destination workspaces are preserved. Duplicate/conflict results count whole workspaces. Failure rolls back owned files; failed rollback lists recovery paths. See docs/personal/profile-import.md for bounds, state order, limitations and recovery.

Appearance import is a separate two-method lease on SettingService: whitelist locale, localePreference and bounded desktopZoomLevel; source settings are read-only, target conditional merge uses the existing settings queue/file lock/atomic writer. Theme and credential settings remain unsupported; history has its own protocol below. Existing locale fields are preserved together, all unknown personal settings retained, no migration performed on the source.

History import is a separate two-method offline preview/confirm lease. Original db+wal are copied by stable no-follow reads; SQLite opens only private staging. Pinned 24-migration checksums, current branch and visible-text filtering produce HistoryImportBundle values. No original SHM writes, no tools/reasoning/permission/queue/workflow input. Caller-injected target commit owns new IDs, transactional inert persistence and recoverable project/task registration. The source owner never materializes a runtime or replays operations. See docs/personal/profile-import.md for subset exclusions and the target adapter contract/tests.

# Official profile import — supported subset

Owner: MemoryService delegates to the personal-profile-import adapter. UI owns only the entered source path and preview; the adapter owns one expiring preview lease. Explicit user action only; no startup discovery, profile scanning, or real-profile acceptance tests.

## Verified formats and limits

Upstream 3.16.2 stores project Markdown at `<profile>/cli/memories/projects/<slug>-<16hex>/memory/*.md` (core/memory/project-root.ts). Copy this subset only. Preserve the exact project ID and Markdown bytes; do not follow Markdown links, relocate projects, or execute content. Project identity/path must still match to use the imported memory. Imported prose remains untrusted background data, subject to the existing memory instructions. Never promote it to user rules or global preferences.

The SQLite baseline contains schema_migration checksums/app_version, session/message/part, workflows and permissions. It is deliberately NOT opened or copied, including WAL/SHM: a live database needs SQLite online backup plus schema-aware semantic merge. In the memory category, sessions, registered projects, settings, login credentials, encrypted/host-bound data, indexes, global memory and all non-Markdown files are unsupported. The separately confirmed language/zoom increment below supports a narrow subset of settings. UI states this before preview/confirmation; no promise of whole-profile compatibility. Arbitrary secrets embedded in user Markdown cannot be reliably identified: UI asks users to inspect source Markdown and exclude sensitive material before importing; common private-key/token patterns abort preview as an extra check.

## State and sequence

`source input → read-only validated snapshot → preview lease (10 minutes) → explicit confirm → revalidate source + target → exclusive destination create → report`

One preview per service, replaced by later previews; confirm consumes the lease. Calls with invalid/expired tokens fail. UI disables edits while requests run and clears obsolete previews whenever the input changes. Copy reads source only, never writes/locks it. Stable no-follow file handles plus complete rescan/hash before copying reject observed source changes; this does not claim a transactional snapshot of an active source. UI tells users to close the official app first. Any database remains untouched, so no WAL consistency claim is made.

Reject symlinks in every existing ancestor and enumerated tree entry, unsafe Windows names/ADS/reserved names, case-folded filename aliases, oversized files (256 KiB), oversized imports (8 MiB/500 files/100 projects), malformed UTF-8, and unknown layouts. Exact workspace identifiers only. Destination must be disjoint from source. Existing workspace directories are never merged: identical imported Markdown means duplicate, otherwise conflict; skip the entire workspace to preserve references. Missing workspaces use mkdir-exclusive admission and wx files. On error remove only files/directories created by this operation; if rollback fails, report exact recovery paths. A process crash may leave a partial new workspace; a repeat preview reports it as conflict, never overwrites it. Recovery is manual deletion of that *personal* workspace after inspecting it, then retry. No durable background jobs or auto-resume.

## Acceptance

Synthetic fixtures only: preview counts without writes; explicit lease confirmation; exact bytes and unchanged source; repeat dedupe; whole-workspace conflicts; source changes; denied symlinks/Windows names/secrets/unknown structure; destination containment; stale token; partial failure cleanup. UI verification: input→preview→confirm and request/error states; desktop/narrow layouts and both themes remain required manual checks unless automated browser evidence is captured. Linux tests do not establish Windows acceptance.

## Non-sensitive settings increment

Actual upstream setting.json lives in the home profile's `v2/setting.json`, independent of custom conversation dataBaseDir. Read it through stable read-only handles, never SettingService.get on the source (get may migrate/quarantine). Only locale, localePreference and integer desktopZoomLevel (-3..5) are extracted; reject unsupported values and omit every other field including connection data. Missing legacy localePreference derives from locale using the existing migration rule. Theme is NOT in this file: `ui/useTheme.ts` and `ui/store/index.ts` persist zcode-theme in Chromium localStorage. Its LevelDB may contain authentication/site data and require an offline database snapshot; theme import is unsupported, use the personal app's existing Theme picker.

A separate preview/confirm lease is owned by the appearance importer, invoked through SettingService. Confirmation verifies the whole source settings file hash (without returning/logging excluded fields), then enters SettingService's existing write queue and file lock. It re-reads raw personal JSON inside the lock, imports only absent fields and returns preserved keys. Locale and localePreference form one group: if either already exists, preserve both to avoid inconsistent language state. The same atomic destination writer used by settings is reused. No whole settings-file replacement from official data. Existing values, including defaults already persisted by the personal app, count as conflicts and are kept. UI explicitly reports counts/keys and restart requirement; no false cross-window instant-apply claim. If atomic write fails, existing atomic recovery semantics apply; there is no coupled transaction with memory import, so each category is separately confirmed and reported.

## Complete-session compatibility investigation and boundaries

The safe text-history increment below does **not** migrate every session-data category. The actual runtime database is `cli/db/db.sqlite` (24 upstream migrations through the appended shared `0024_session_database_identity`; personal history versions extend SessionRevert JSON rather than the database schema); the task index is `v2/tasks-index.sqlite` via getTasksIndexDatabasePath. The runtime stores session.project_id/workspace_id/directory/path/parent_id, JSON message.data and part.data, accepted session_input, session_target, session_task_link, workflow/dwf state and permissions. The task index independently stores tasks keyed by workspace_key+task_id, workspace_identity/path, groups, automations and off-peak jobs; source-server workspace migrations maintain alias and generation ledgers. Copying only session/message/part would omit sidebar/project ownership and could resurrect queued work. Raw data may also include tool-input credentials or sensitive transcript content, unlike an explicit safe-fields schema.

The broader full-fidelity migration would require: read-only SQLite online backup of each explicitly selected source database into private staging (include WAL snapshot through SQLite, never copy main file alone); verify immutable migration IDs+checksums; reject future schemas; run existing migrations only on temporary copies; validate JSON records against corresponding contract versions; reconstruct project/task identities and remap collisions; exclude permissions, credentials, active input/workflow/automation execution and remote connection settings; import inert history with explicit source provenance; commit target databases and index as a journaled recovery unit. Cross-database source snapshots are not atomic: require a closed source app or a stable generation check. Existing sourceServerWorkspaceAliasRepo.ensureDatabaseBackup demonstrates SQLite backup, but its migration API mutates live local aliases/databases and must not be called on official profile data.

Before enabling sessions, synthetic fixtures must cover WAL-only writes, 24-migration checksum compatibility, unknown future schemas, malformed JSON, task/session link mapping, filename/workspace relocation, conflicting IDs, partial multi-database commit/restart recovery, and proof that queued commands/external actions are not replayed. The implemented text-history adapter below deliberately does not implement these broader execution-data transfers. Ineligible sessions remain in the official app; users can import supported memories/language/zoom and eligible local text-history sessions, and select the theme manually. No real user profile was opened during this investigation or testing. SQLite opens only private synthetic fixtures or staging copies after an explicit product action.

## Safe resumable text-history increment

The implementation now stages the explicitly selected **closed/offline** source `cli/db/db.sqlite` plus optional `-wal` using bounded no-follow read handles. It verifies byte hashes and file identity/timestamps twice across the copy. It never opens the original with SQLite: a read-only SQLite connection may write SHM, so only the private temporary copies are opened. Original `-shm`, credential/config files and project contents are not opened by this category. Staging is 0700 with 0600 database files and is removed in finally on both success/failure. A crash can leave a private temporary directory; it is not a registered import or resume job. This is an offline-copy requirement, not a claim of atomic cross-file capture from an active application.

The staged database must pass quick_check and exactly match all 24 pinned current migration IDs/checksums (including appended 0024 identity); future/older/mismatched schemas fail closed. No migration executes on the source. Only nondeleted interactive sessions with local absolute directories and null workspace_id are eligible. Identity-bound/remote projects need explicit remapping and are skipped, never reinterpreted as local paths. Old session IDs and database identity are provenance only; new IDs are assigned by the target runtime. Per-session content hash plus source database identity (or source-path hash when absent) plus source session ID forms the deterministic sourceKey; an identical snapshot can be retried safely.

Source branch selection follows the verified rewind contract's kept IDs + cut cursor / created message semantics, preserves kept order and rejects missing/ambiguous cursors. Unrecognized legacy revert formats and compacted sessions that require context conversion are skipped. Only visible user/assistant TextPart values enter the bundle. Synthetic/model-only/hidden/summary messages, synthetic/ignored text, tools, reasoning, files, permissions, inputs, goals, workflow and execution state are excluded. Common key/password/token patterns reject the session without returning its text; arbitrary free text cannot be guaranteed free of sensitive information. The UI must say this before confirmation.

Preview returns eligible titles/project directories/counts and explicit skipped reasons, never message bodies or credentials. Confirmation consumes the 10-minute lease, restages/rechecks the source fingerprint and only then calls the injected target commit owner. That owner uses a new inert-history persistence command, atomic target IDs/message/part/provenance storage, and recoverable task/project registration; it must not materialize/resume a runtime while importing. Newly imported history can receive a new user request explicitly after import. No historical command/external action is replayed. If target registration fails after persistence, retrying the same sourceKey recovers the sidebar index rather than creating a second session. Target transaction/registration tests are owned by the target adapter; source tests verify WAL-only content, byte/mtime/ctime/filename invariance of **every original DB directory file**, checksum drift/future schemas, edited-branch filtering, secret exclusion, symlinks, changed source and consumed-lease retry.

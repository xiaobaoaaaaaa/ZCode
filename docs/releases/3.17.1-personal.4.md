# ZCode Personal 3.17.1-personal.4

基于官方 3.17.1 与 Personal.3，修复子代理历史查看、完成态执行过程折叠与手机远控入口，并启用 Personal 应用内更新。

## 修复

- 主代理在工作区内切换到子目录后，新建子代理会保存实际执行目录。此前冷恢复把这个目录当成工作区归属，可能报 `project.session-lineage-invalid`。现在通过持久化父链确认所属主任务，同时保留子代理的执行目录；兼容旧记录，无需迁移数据库。缺失、已删除、成环、跨身份或越界的父链仍拒绝。
- 主会话、子代理详情和后台自动唤醒轮统一聚合连续思考与普通工具调用。完成后展开“已工作 xx 秒”仍显示可独立展开的“执行过程”；正文、错误和需要交互的内容保持可见。
- 手机扫描 Personal 二维码时，完整版本号可能指向官方未部署的页面而返回 Not Found。二维码与配对后的版本握手现在共同使用对应上游页面版本；设备登记仍保留完整 Personal 版本。仅在旧桌面上手改 URL 不足以修复握手后的再次跳转，需要安装本版本。

## 应用内更新

- Personal 更新只读取本仓库公开 Release，按完整版本号识别 Personal 序号升级；稳定通道排除预发布，启用预览版后可接收公开预发布，草稿始终不进入更新源。
- Windows/Linux 支持检查、下载进度、取消、跳过与重启安装；Linux 保持当前包格式，下载验证 SHA-512。macOS 因当前签名方式仅检查更新并提供“打开下载页”，手动下载新版本安装。
- 首次启用需手动安装本版本一次。既有 Personal 独立身份及数据目录保持不变。

## 验证

- CLI 冷恢复回归 134 项通过，覆盖真实 SQLite 关闭重开、本地/远端身份、两种 delivery 语义、旧记录及拒绝边界。
- 真实组件浏览器回归 12 项通过，覆盖主轮、后台轮、历史入口，桌面/手机触屏宽度与深浅主题。
- 桌面回放覆盖普通完成态、后台完成态，以及真实 Bash cd → Agent 派发 → CLI 重启 → 重新打开详情；原子代理 ID、正文与主列表隔离均保留。
- 隔离 relay 与真实 Desktop Main 验证二维码、bootstrap 和设备登记版本；原有远控启动失败及登出清理场景通过。页面版本 smoke 覆盖 9 种输入。
- 根类型检查、Lint、架构检查及受影响 CLI 包检查通过；Lint 保留既有警告。CLI 使用包级类型检查与完整构建验证。

应用更新隔离 Electron 场景 17 项、浏览器交互 4 项、官方更新源安全回归 24 项通过；发布相关工具回归 10 项通过。真实 Windows/Linux 跨版本覆盖安装与升级后数据保留尚未验证。

上述桌面行为在 Linux 上验证；手机布局和本地 relay 回放不等同于实体手机 OAuth、公网远控及各平台完整功能验收。既有后台/浏览器候选用例保持 pending-review。

## 下载与安装

沿用五个平台的原生打包与启动检查，提供 Windows x64 EXE、macOS x64/ARM64 DMG 与 ZIP、Linux x64/ARM64 AppImage、DEB、RPM 和 Arch 包，共 13 个安装包，以及 `SHA256SUMS`、`release-manifest.json`。

保留 Personal 独立安装身份和数据目录，可与官方版并存。macOS 使用 ad-hoc 签名，未进行 Developer ID 签名或公证；Windows 未使用 Authenticode。包内保留第三方声明及上游登记的材料缺口，基础许可证检查不等同于完整材料审计。
